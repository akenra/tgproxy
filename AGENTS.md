# TG PROXY CHECKER: ПРАВИЛА РЕПОЗИТОРИЯ

Правила для всех, кто меняет код: людей и ИИ-ассистентов. Это не рекомендации: отклонение - повод вернуть изменение на доработку.

## OVERVIEW

- Назначение: кроссплатформенная GUI-утилита, которая качает публичные списки MTProto-прокси, проверяет каждый полным хендшейком и кладёт живых в буфер обмена одним списком для вставки в Telegram.
- Стек: Python 3.9+, tkinter; приложение - один файл `tgproxy_gui.py`; единственная внешняя зависимость - `mtproxy-checker`.
- Тесты: `pytest` + `pytest-cov`; блокирующий gate покрытия 95% задан в `pytest.ini`. Фактическое покрытие - 100% (statement и branch); держать его, а не просто порог.
- CI: `.github/workflows/tests.yml` - джобы `coverage` (windows-latest, эталонная среда) и `unix` (ubuntu, xvfb + pytest-forked). `.github/workflows/release.yml` - сборка бинарей трёх ОС по тегу `v*`.

## COMMANDS

- Тесты: `python -m pytest` (gate уже включён в pytest.ini).
- Запуск приложения: `python tgproxy_gui.py`.
- Прогон без покрытия: `python -m pytest -o addopts=''`.
- Локальная сборка: `pyinstaller --onefile --windowed --name tgproxy_gui tgproxy_gui.py`.

## COMMIT MESSAGES (MANDATORY)

Формат - Conventional Commits: `<type>(<scope>): <summary>`.

- `type` в нижнем регистре: `feat` `fix` `docs` `style` `refactor` `perf` `test` `build` `ci` `chore` `revert`. Точно по смыслу: тесты - `test:`, CI - `ci:`, `chore:` - последнее средство.
- `scope` в нижнем регистре, по словарю репозитория: `gui`, `tests`, `ci`, `release`. Пустой лучше, чем выдуманный.
- `summary`: императив («добавить», «исправить»), до 50 символов, без точки в конце.
- Тело через пустую строку: что и почему; до 72 символов в строке. Для тривиальных правок можно опустить.
- Описания по-русски; `type(scope)` остаётся английским.
- Один коммит - одно логическое изменение; не смешивать рефакторинг со сменой поведения.

Пример:

```
fix(gui): переносить выделение вместе с прокси

После сортировки живые-первыми селект уезжал на другую строку;
выделение привязано к url, а не к индексу.
```

## COMMENTS, DOCSTRINGS, DOCUMENTATION

Человекочитаемые тексты (комментарии, docstrings, README) - по-русски; идентификаторы и API - по-английски, как в коде.

- Комментарий объясняет «почему», а не «что»: `# защита от двойных нажатий` - хорошо; `# присваиваем x = 1` - шум, удалять.
- Короткие предложения, активный залог, один термин для одного понятия в пределах файла.
- Без типографских unicode-символов (длинное тире, стрелки): только ASCII-пунктуация - дефис, запятая, скобки.
- Никаких следов обсуждений и подписей инструментов в артефактах: сообщение и комментарий описывают изменение, а не диалог вокруг него.

## TESTS

- Дефект чинится от теста: сначала падающий регресс-тест (RED), затем фикс (GREEN).
- Тесты не ходят в сеть: `fetch_all` и `alive` подменяются моками; реальные соединения - только в ручных прогонах приложения.
- Покрытие просело - добрать; gate ниже 95% не опускать никогда.
- Tk-тесты на Linux идут через pytest-forked: Tcl 8.6 падает в общем процессе с потоками воркера. Это защита, а не костыль.

## CONVENTIONS

- Минимум сущностей: один файл приложения, одна зависимость, stdlib вперёд. Новая зависимость принимается только с обоснованием.
- `gc` выключен на весь сеанс приложения (`gc.disable()` при импорте): цикл коллектора в фоновом потоке при живом Tcl роняет интерпретатор. Это осознанное решение, оно задокументировано в коде; не «возвращать как было».
- UI-тексты короткие и по-русски: кнопка называет действие, статус отвечает на «что произошло».
- Секреты и локальные пути не попадают в репозиторий ни в каком виде: ни в код, ни в тесты, ни в документацию, ни в сообщения коммитов.

## RELEASE

- Тег `vX.Y.Z` на main запускает release-воркфлоу: PyInstaller собирает windows/macos/linux-бинари и прикрепляет их к GitHub Release.
- Тесты в сборочных джобах не дублируются: их прогоняет workflow tests на тот же коммит.
